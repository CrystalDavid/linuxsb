# UI 设计规范

适用版本：`1.1.1 / 1001001 / build 3`。本版本的 Cloudflare、头像和性能修复不改变既有 UI 几何、字体、颜色、交互或冻结底栏。

本文件是烧饼社区视觉 token 与共享组件的规范源。实现值以 `DesignSystem.ets`、共享组件和资源颜色为准；页面不得通过局部魔法数字悄悄建立第二套视觉系统。

## 设计原则

- 简约、蓝色、HarmonyOS 原生；背景保持单一层级，交互层才使用玻璃。
- 一个控件只允许一个采样层：API 26 为 `systemMaterial`，API 23–25 为 `backgroundEffect`；两者不得叠加。每个玻璃控件只保留一个细边缘和一圈中性阴影。
- 选中状态依靠品牌蓝文字/图标、极淡选中胶囊和局部蓝光表达，不使用厚白填充。
- 深色模式必须降低白边与白色填充，不能把玻璃做成发亮的银色描边。
- 正常业务图标优先使用系统 `SymbolGlyph`；需要精确轮廓时使用 ArkUI `Path`，不使用位图模拟可参数化图标。

## 字号体系

业务文字固定为以下 **13 种字号**。`SymbolGlyph`、`Path`、头像首字母和纯图标的几何尺寸不计入业务文字字号；新增 `Text`、`Button`、`TextInput`、`TextArea` 时必须引用 `Typography` token。

| Token | 字号 | 场景 | 常用字重 |
| --- | ---: | --- | --- |
| `MICRO` | 11vp | 底栏标签、极小状态、次级徽标 | Regular / Medium |
| `CAPTION` | 12vp | 说明、板块简介、加载提示、标题栏筛选标签 | Regular；选中 Medium |
| `METADATA` | 13vp | 作者、回复数、时间、普通标签、代码正文 | Regular |
| `BODY_SMALL` | 14vp | 辅助正文、筛选 Chip、作者优先副层 | Regular / Medium |
| `BODY` | 15vp | 正文、输入、普通操作文字 | Regular |
| `LIST_TITLE` | 16vp | 紧凑主题流、折叠小标题 | Regular / Bold |
| `TOPIC_TITLE` | 17vp | 首页主题、板块名称、具体板块主题 | Medium（500） |
| `SECTION_TITLE` | 18vp | 页面内分区标题、登录门禁标题 | Medium / Bold |
| `CONTENT_TITLE` | 20vp | 用户名、空状态标题、内容级标题 | Bold |
| `PAGE_TITLE` | 22vp | 设置、发表、详情、登录等压栈页面标题栏 | Bold |
| `HEADLINE` | 24vp | 主题详情主标题、展示级头像字母 | Medium / Bold |
| `DISPLAY` | 26vp | 诊断页展示标题 | Bold |
| `ROOT_PAGE_TITLE` | 28vp | 首页、板块、称号、我的四个根页面左上角标题 | Bold |

正文默认行高为 23vp，长文阅读行高为 25vp。兼容别名只能映射到上述 token，不得产生第 14 种业务字号。

| --- | --- | --- |
| 间距 | 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32vp | 从局部紧凑间距到页面分区间距 |
| 页面横向边距 | 12vp | 手机主内容安全边距 |
| 圆角 | 6 / 8 / 12 / 18vp | 小标签、内容块、卡片、较大容器 |
| 满圆胶囊 | `Radius.PILL` | 分段、玻璃按钮、圆形操作 |
| 手机内容最大宽度 | 720vp | 列表与普通页面 |
| 详情内容最大宽度 | 840vp | 主题详情 |
| 平板双栏断点 | 900vp | 小于此值保持单栏 |

## 色彩

### 基础语义色

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#F8FAFC` | `#0B0F12` |
| 主文字 | `#17202A` | `#F1F5F8` |
| 次文字 | `#556270` | `#B1BCC6` |
| 品牌蓝 | `#0A59F7` | `#5B8FF9` |
| 品牌软背景 | `#E8F1FF` | `#1B3158` |

`surface`、`surface_secondary`、`surface_elevated` 与 `settings_group_bg` 必须分别等于对应主题的页面背景。它们只保留语义名称，不得形成肉眼可见的白板或另一块深灰底：称号、交易、空态、表单和列表分组通过间距、0.8–1vp 细边及圆角建立层级。设置总览的两行系统样式卡片是唯一结构例外，只能使用 `settings_overview_card_bg`（浅色 `#FFFFFF` / 深色 `#151A20`）；主题选择预览中的白色小样属于被预览内容，也不受本条约束。

### 状态胶囊

- 置顶：蓝；精华：紫；热：红；抽奖中：粉；进行中卡片：青；已结束卡片：灰。
- 标签文字和软背景必须成对使用；深色模式使用专用高对比资源，不能直接复用浅色前景。
- 不得用同一种灰色代替所有业务状态。

## 共享玻璃参数

所有玻璃控件（FAB、回复/搜索输入、标题栏筛选按钮与下拉菜单、板块 Chip、发帖输入框与底部 Tab 托盘回退层）共用唯一一套“通透”光学参数。不得为单个组件恢复奶白、厚霜或不透明白色底板：

| 公共参数 | 规范值 |
| --- | ---: |
| 外边缘 | 普通组件 0.8vp，`bottom_tab_bar_highlight`；只承担液态高光边，不形成白壳 |
| 外阴影 | 普通组件半径 10vp、Y 偏移 2vp；底栏半径 12vp、Y 偏移 3vp |
| 选中层边缘 | 0.9vp |
| 选中层阴影 | 半径 7vp，Y 偏移 1vp |

### 全局通透配方

提取自系统相册、华为应用市场与参考音乐控件的透亮层级：极低 alpha tint 让底层色块与明暗穿透，适度提高饱和度，避免高亮度与大半径把内容抹成白雾。当前 target 24 产品由唯一一层 `backgroundEffect` 保持这一视觉方向；API 26 通用原生材质必须由另行建立的 target 26 产品验证，不能在文档中提前标为已命中。

| 参数 | 规范值 |
| --- | ---: |
| 采样半径 | 4vp（轻度打散文字边缘，同时保留头像、标签与图片色块） |
| 饱和度 | 1.42 |
| 亮度 | 0.98（避免亮色页面把玻璃抬成白膜） |
| 采样 tint | `glass_translucent_tint`（浅色 `#080A59F7` / 深色 `#0800B8FF`） |

设置中不再提供玻璃风格选择。`GlassStyle.init()` 会把旧版本曾持久化的奶白值强制迁移为 `TRANSLUCENT`，避免升级后局部组件继续使用废弃参数。当前 HDS 系统路径使用能力探测后的 `ADAPTIVE`；普通组件仍是 target 24 的单层回退。未来 target 26 产品可将该唯一风格映射为 `ULTRA_THIN`，但不得与回退双采样。

称号中心顶部六枚横向滚动胶囊及交易页三枚子页胶囊也属于交互玻璃：每个按钮只允许一层上述 `backgroundEffect`、0.8vp 高光边与 10vp 单圈阴影，并关闭系统默认 pressed/hover 蒙层。未选中项使用透明背景以保留下方页面色与相邻内容；选中项使用主题主前景实底、页面色文字，维持截图参考中的明确黑/白选中态。称号卡片本体不是玻璃组件；除“我的称号”使用 `gacha_rarity_n_soft` 浅灰底外，其余结构卡片继续使用页面同底色。

### 底部 Tab 托盘主玻璃

当前可见底栏是自绘托盘，`HdsTabs` 只负责页面容器并隐藏自己的视觉栏，避免两层材质重复采样。API 23–26 运行当前 target 24 HAP 时，托盘始终使用唯一一层 4vp / 1.42 / 0.98 / 低 alpha tint 的 `backgroundEffect`。标题栏等 HDS 组件仍独立执行能力探测并优先 `ADAPTIVE`。

| 参数 | 规范值 |
| --- | ---: |
| 采样半径 | 4vp |
| 饱和度 | 1.42 |
| 亮度 | 0.98 |
| 采样 tint | `bottom_tab_bar_bg`（浅色 `#080A59F7` / 深色 `#0800B8FF`） |

托盘的按钮、移动指示器、图标与标签参数维持冻结线不变；其他 40/42/52vp 小控件与共享玻璃表保持一致。禁止恢复 60vp 大半径、亮度增益、厚白 tint 或双层采样——这些组合会把托盘变成灰白色蒙层。

### 浅色玻璃

| Token | 值 | 作用 |
| --- | --- | --- |
| `bottom_tab_bar_bg` | `#080A59F7` | 极低 alpha 冷色采样基底 |
| `bottom_tab_bar_highlight` | `#A8FFFFFF` | 细而清晰的液态高光边缘 |
| `bottom_tab_bar_shadow` | `#240D1B2A` | 低强度中性外阴影 |
| `bottom_tab_selected_bg` | `#145B8FF9` | 极淡品牌蓝选中胶囊 |
| `bottom_tab_selected_glow` | `#240D1B2A` | 浅色下的低强度中性局部光晕 |

浅色模式不能让选中胶囊与页面背景融为一体，也不能用不透明白色切断下方内容。

### 深色玻璃

| Token | 值 | 作用 |
| --- | --- | --- |
| `bottom_tab_bar_bg` | `#0800B8FF` | 极低 alpha 冷色采样基底 |
| `bottom_tab_bar_highlight` | `#54FFFFFF` | 克制但可见的细边缘 |
| `bottom_tab_bar_shadow` | `#50000000` | 降低强度的黑色外阴影 |
| `bottom_tab_selected_bg` | `#0A5B8FF9` | 极淡品牌蓝选中胶囊，不叠白色 |
| `bottom_tab_selected_glow` | `#245B8FF9` | 低强度蓝色局部光晕 |
| `brand_primary` | `#5B8FF9` | 深色模式选中图标与文字 |

深色模式的目标是“烟熏底 + 蓝色语义 + 微弱蓝光 + 细白边”。禁止恢复 `#C2FFFFFF` 一类高亮白边，禁止在选中胶囊上再叠加白色半透明背景。旧 `hds_floating_action_*` 资源不是共享组件的规范入口；正式圆形按钮仍须引用上述 `bottom_tab_*` token。

发表主题页布局顺序为：标题输入（48vp）、正文输入（最小 260vp）在上，图片选择行与缩略图在正文之下，板块选择器在下；顶部标题栏与标题输入保持 8vp 间隙。标题与正文输入框统一为 `Radius.MD`，正文不再使用过大的胶囊圆角。

所有圆形玻璃按钮应共享同一采样、边缘和阴影参数；不同业务场景可以有 40、42、52vp 的明确尺寸，不能随页面临时放大。

## 底部导航冻结线

- 四栏固定为“首页 / 板块 / 称号 / 我的”，搜索位于首页右上角。首页发布入口不占用 Tab 槽位，作为与托盘同高的独立圆形玻璃按钮固定在右侧；“我的”同位置为系统设置按钮；板块/称号无右侧动作且托盘弹性居中。
- 板块目录行只显示 16vp 色标、17vp/500 板块名、12vp 简介和右侧 13vp 真实主题数；不显示进入箭头，整行点击区域保持不变。
- 首页使用 ArkUI `Path`，门洞透明、底部横梁封闭；板块、称号、我的使用系统填充 Symbol。
- 四枚图标在 28×26vp 光学盒中以各自中心统一缩放 0.92，并统一下移 0.7vp；标签为 11vp、16vp 行盒。
- 只允许一个玻璃托盘和一个连续移动指示器，不叠加 Button 默认 pressed/hover 状态层。
- `ImmersiveBottomTabBar.ets` 与关联入口已冻结，修改前必须取得用户明确同意；交付前运行 `scripts/CheckBottomTabVisualLock.ps1`。

## 列表与内容排版

- 首页仅保留“标题优先”和“作者优先”。标题优先头像 48vp；作者优先头像 38vp。“我的”主题/回帖流单独使用 40vp 头像和 6vp 标题—元信息间距，让分类标签与作者行仅轻微上移，不改变其他列表。
- 两种首页主题标题均为 17vp / 500；作者、回复、时间为 13vp。
- 板块目录名和具体板块主题标题与首页相同，均为 17vp / 500。
- 主题详情主楼和回复使用头像居左、作者/正文居右；正文 15vp，长文行高 25vp。滚动折叠标题栏内的分类标签相对标题起点右缩 12vp。
- 列表使用真实头像；仅在缺失或加载失败时使用首字母回退。
- 回复行只保留“#楼层 · 时间”，站点抓取到的交互小字与导航文案不混入正文和元信息；点赞、举报、回复均为独立 30vp 图标胶囊，不再显示“回复 #N”引用指示。举报必须先选择原因，并再次确认站点 500 积分押金规则后才提交。
- 称号中心六个子页的短内容和空态都从分段标签栏下方开始，不得在剩余视口内垂直居中；滚动内容使用最小视口高度并固定 `FlexAlign.Start`，数据增长后仍保持正常滚动。
- 称号抽取必须显示服务端实时积分、拥有数/总数及完整称号池；三个熔炼配方必须固定三列同屏、不得横向滚动，配方标题和操作按钮之间的“已选 / 可熔炼 / 消耗 / 产出”拆成四个单独行，第三张卡的标题色与前两张一致，并在配方下方提供可选材料列表。
- “我的”功能入口固定为两行四列：第一行“我的主题 / 我的回帖 / 我的收藏 / 我的消息”，第二行“我的私信 / 我的积分 / 我的烧饼 / 个人设置”；两行间距 8vp。八个入口均使用鸿蒙原生单色填充 Symbol（`doc_text_fill / message_fill / bookmark_fill / bell_fill / envelope_fill / coins_badge_coin_fill / wallet_fill / gearshape_fill`），禁止恢复彩色 Emoji。主题/回帖流必须在列表上方显示对应栏目标题。
- “我的私信”列表采用头像、联系人、预览和时间组成的无外框会话行；点击整行进入 `/direct_messages/{id}` 的原生会话页。会话按双方方向显示气泡，并固定复用主题详情的“图片加号 / 输入框 / 发送”回复栏；回复栏额外避让根页面 94vp 悬浮底栏，不得穿模或被遮挡。原站私信表单仍按纯文本 500 字契约提交，图片经既有匿名图床转成外链文本。
- “我的烧饼”使用专用顺序布局：余额卡左右边界由列表项内边距约束，图标不得超出页面；其后紧接“兑换码充值”输入框与“立即兑换”按钮，再显示“收支明细 / 充值申请”栏目标题及服务端真实空记录。不显示“兑换成功后立即到账 / 连续输入错误 / 还没有兑换码 / 最近 30 条 / 最近 10 笔”等网页说明。积分、收藏、消息使用与主题列表一致的分隔行；消息存在主题链接时必须显示“查看原帖”，并跳到服务端链接携带的回复位置；通知作者使用 16vp，作者行与正文使用 4vp 间距、正文 20vp 行高。头像下的称号与积分分成两个独立文本节点。
- “个人设置”读取 `/profile` 并原生展示用户名、UID、邮箱、注册时间、积分和登录状态；用户名、头像、简介、密码修改分别沿用原站 `/username_change`、`/avatar_upload`、`/profile` 表单契约。用户名修改必须显示原站“当前密码验证 + 10 积分”规则；简介使用独立“保存资料”，密码使用独立“确认修改”，两者不得共用提交按钮。预置头像可横向选择，图库头像先居中裁成 200×200 JPEG，再由用户二次确认上传。

## 交互与可访问性

- 分段控件既支持点击，也支持水平拖动；选中状态必须先更新本地响应式状态，再持久化。
- 首页与板块页标题栏右端为筛选按钮：显示当前排序文字（新评论 / 新帖子 / 精华 / 抽奖 / 发卡 / 足迹），点击展开六项玻璃下拉菜单，选中后按钮文字与列表同帧切换；板块目录页不显示筛选按钮。
- 称号交易页的“在售交易”已选按钮支持双击刷新当前页；双击只重新执行当前筛选与页码对应的 GET，并以“在售交易已刷新”提示完成，不改变筛选、页码或交易数量。
- 搜索空态提示层必须对点击穿透（`HitTestMode.None`），不得遮挡输入框与范围选择按钮。
- 搜索范围选择不得使用底部 ActionSheet；使用与首页筛选一致的原生玻璃下拉菜单，范围文字、勾选符号、展开箭头、输入光标和提交箭头均使用主题主前景色（浅色黑、深色白）。
- 图标按钮提供 `accessibilityText`；纯装饰节点不承担点击语义。
- 默认 pressed/hover 层若造成双轮廓或黑闪，应关闭并由唯一移动指示器表达状态。
- 布局检查不仅看逻辑坐标，还要看可见边界、文字光学居中、状态栏安全区和深浅色对比。
- 图片插入位置：点“添加图片”那一刻用 `TextAreaController` / `TextInputController` 的 `getCaretOffset()` 快照光标位置，与附件列表平行保存（删除缩略图时同步移除对应偏移）。提交上传成功后，按各自光标位置把 `![](url)` 插入正文，而不是一律追加到末尾。
- 多张图片按光标位置降序插入（先插后面的，避免把未插入项的位置顶偏），同一位置的多张图按选择顺序的逆序插入，保证正文中出现顺序与选择顺序一致。
- 光标位置取不到或越界时退化为末尾追加，与旧行为一致，保证任何异常都不会丢失图片；回复栏先按原始草稿插入再整体 `trim`。
